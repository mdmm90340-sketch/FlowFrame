# 1.2.1 结构与效率优化验收

日期：2026-09-12。对比基线为本地 1.2.0，提交 `e659f3c29cf94af235579afbd57c32f1580c9666`。此次保持现有用途、UI 操作、公开媒体范围、历史格式、签名和原生组件，重点减少持续发生的重复工作。版本为 1.2.1 / 7，仅本地交付。

## 改动及可观测结果

| 路径 | 优化前 | 优化后与验证 |
| --- | --- | --- |
| 真实 VM 的 5 次下载进度更新 | 重复写入输入草稿 **5 次**，另一条未变化的任务行被重建 **5 次** | 同一设备测试两项均为 **0 次**；进度本身正常更新 |
| 1,000 条历史中一条记录连续更新 5 次 | 原实现每次全量转换任务记录 | 新投影模块的 JVM 测试只产生 **5 个变化行**，其余 999 行每轮沿用原对象；不是整页帧率或内存峰值测量 |
| 空闲任务存储 | 常驻协程每 1.5 秒唤醒检查 | 没有待保存内容时没有延迟写入协程；有变化时只安排一个写入，成功后结束 |
| 同值更新 / 删除不存在的记录 | 同值更新改变时间戳和文件；无效删除重写历史 | 文件内容/修改时间和未变化记录对象保持，设备测试通过 |
| 等待并发名额 | 每 250 毫秒轮询，空位释放后可能还需等下一轮 | 名额或设置变化唤醒；释放、增减上限、取消等待及多任务竞争测试通过 |

`TaskUiProjector` 统一任务展示转换，接收显式网络约束与缩略图快照；主题、目录或并发设置变化不再重做整份任务展示。缓存随记录删除收缩，网络原因与缩略图刷新保留。`EditorRecoverySnapshot` 将恢复字段与进度、诊断、主题等无关状态分开，去重后再写入 `SavedStateHandle`。

`TaskStore` 在加载、添加和变换入口清理临时缩略图地址，已经清理的记录直接复用。普通进度在原有约 1.5 秒窗口内合并，终态立即持久化；写入失败保留最新待保存快照，等一个完整窗口再重试。失败测试阻塞新建测试目录，等待实际失败尝试结束，再恢复目录并重新打开记录验证。

并发门在锁内读取原始设置流，避免异步派生状态滞后导致降低上限后额外启动。运行中的下载不因降低上限而被中断；取消后仍通过原有 `NonCancellable` 清理释放名额。Worker 仅对需要展示的进度回调解析指标，并直接使用存储更新结果，减少重复历史查找。

历史 JSON 仍整体序列化，任务列表仍需遍历；此轮没有将其改成数据库或分页加载。收益主要是减少无效写入、对象复制和定时唤醒，不宣称任意大小历史都变成恒定成本，也没有测量耗电、帧率或互联网下载吞吐提升。

## 性能测量方法

使用同一 API 35 x86_64 普通 4 KiB 虚拟机、相同显示/内存/CPU 配置和保留的 7 条任务历史。保留应用及 OS 缓存，排除系统启动后的首次启动和两次预热；每次强制停止并确认进程退出，等待 1 秒后 `am start -W`，启动后静置 3 秒，共测 7 次。采样期间不运行 Gradle。

旧版 `TotalTime` 为 438、352、428、415、388、434、416 ms，中位数 **416 ms**。这是缓存就绪后的冷进程 Activity 启动，不是首次安装的原生解压或引擎完全就绪；宿主后台负载未被严格控制，不能把一次本地对比当成普遍提速结论。

新版排除的两次预热为 390、377 ms；7 次采样为 **383、375、390、393、541、388、381 ms**，中位数 **388 ms**，范围 375–541 ms。保留了 541 ms 的样本，没有人为剔除。此次本机中位数减少 28 ms（约 6.7%）；样本较少且单次波动明显，只作为局部观察，确定的重复工作减少以设备计数和文件回归为依据。

单次空闲主页内存快照中，PSS 从 31,663 KB 变为 33,048 KB，RSS 从 161,340 KB 变为 141,952 KB。两种指标方向不同，且只有一次采样，**不据此宣称整体内存占用降低**。
