## 签名、内核与 16 KiB

应用 ID 为 `com.flowframe.app`，版本 1.2.0 / 6。正式包启用 R8 与资源压缩，默认手机包仅含 arm64-v8a。原证书 SHA-256：

```text
2ef4b184c1694d1f9813711454c3ea9c15a8d331fe59733e593b78e456f3f0ac
```

固定 yt-dlp 内核未变，SHA-256 为 `E88DBA1F25813F43E9292B676F8D03186757CA0D2011DF4CE54ECD60810019E8`。

最终交付文件的 SHA-256：

| 文件 | SHA-256 |
| --- | --- |
| `FlowFrame-1.2.0-arm64-release.apk` | `92D971A884CAB7A2733A2E01E9468CB1347B60724BF28E31994E6D49B9A891DC` |
| `FlowFrame-1.2.0-x86_64-test-release.apk` | `AE6D19CF61A2BC1F8CC16D5CF3BB2F33602343297E08F5632B6CB54662942698` |

本次发现原 FFmpeg 嵌套包的 5 个 WebP 库只有 4 KiB 对齐，使用官方同版本 1.6.0 源码与固定 NDK r28c 重编两种 ABI。十个库均保留原动态导出/SONAME，LOAD 与 RELRO 校验通过；重打包保留每种 ABI 的 55 个 Unix 符号链接，除这五个库外所有条目内容与 Unix 属性相同。新初始化逻辑按清单 SHA 更新旧解压缓存。

最终 APK 的 ZIP `zipalign -P 16` 检查通过，但递归 ELF 静态检查结果为**失败**：

| APK | ELF 数量 | LOAD 对齐失败 | GNU_RELRO 结束地址错位 | 校验器退出码 |
| --- | --- | --- | --- | --- |
| arm64 | 257 | 0 | **192** | 1 |
| x86_64 | 259 | 0 | **188** | 1 |

两者均无缺失 RELRO、格式或容器错误。所有 LOAD 至少 16 KiB 且偏移同余，但其余上游组件仍有 RELRO 结束地址未按 16 KiB 对齐，例如 `libandroidx.graphics.path.so` 与 `libffmpeg.so`。根据 [Android 官方 RELRO 检查说明](https://developer.android.com/guide/practices/page-sizes#relro)，这是运行兼容风险，需要重编相关组件；不能把 LOAD 或 ZIP 单项通过写成完整 16 KiB 支持。

校验器已改为分别报告 LOAD、RELRO、缺失/格式错误和整体静态结果，15 项合成 ELF、嵌套 ZIP 与 CLI 边界自测通过。源码包含独立工具和重编说明 [WEBP-16K.md](WEBP-16K.md)。实际 16 KiB 的 x86_64 实验镜像中，本次正式包的启动与原生媒体路径通过；这份运行证据与上述静态失败同时保留，不能推广到全部依赖或 arm64 手机。

实验镜像的系统兼容开关未修改。只读查询的 `bionic.linker.16kb.app_compat.enabled`、`pm.16kb.app_compat.disabled` 均为空，包信息也没有相关字段，因此不能据此断言兼容模式已开启或关闭。
